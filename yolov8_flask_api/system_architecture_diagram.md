## 目前問題診斷圖

```
┌─────────────────────────────────────────────────────────────────┐
│                 Cloud Run 容器啟動流程                            │
└─────────────────────────────────────────────────────────────────┘

  容器啟動
     │
     ├─ 步驟 1: 匯入 Docker 映像層
     │          ├─ Layer 1/19 ✅
     │          ├─ Layer 2/19 ✅
     │          ├─ ...
     │          ├─ Layer 18/19 ✅
     │          └─ Layer 19/19 ⏳ (卡住)
     │
     │  【問題】: 映像太大 (~90MB 壓縮後)
     │           包含: Python, PyTorch, YOLOv8,
     │                 Langchain, ChromaDB, etc.
     │           匯入時間過長，可能超時
     │
     ├─ 步驟 2: 啟動 Python 程序
     │          └─ ❌ 未執行 (匯入失敗)
     │
     ├─ 步驟 3: 執行 initialize_services()
     │          ├─ 檢查本地向量資料庫
     │          ├─ 從 GCS 下載 (2-5秒)
     │          └─ 載入 Chroma
     │          └─ ❌ 未執行
     │
     └─ 步驟 4: Flask 監聽 8080
                └─ ❌ 未執行

  Cloud Run Health Check
     │
     ├─ 超時時間: ~10分鐘
     │
     └─ 結果: ❌ Service Unavailable
                (容器從未成功啟動)

┌─────────────────────────────────────────────────────────────────┐
│                      根本原因分析                                 │
└─────────────────────────────────────────────────────────────────┘

1. 【映像大小問題】
   • Docker 映像包含完整 ML 框架
   • PyTorch: ~800MB
   • YOLOv8 模型: ~100MB
   • 其他 Python 套件: ~500MB
   • 總計: 1.4GB+ (未壓縮)

2. 【冷啟動問題】
   • Cloud Run 無狀態容器
   • 每次擴展都需要完整啟動
   • 匯入大型映像需要時間
   • 下載向量資料庫增加延遲

3. 【資源限制】
   • CPU: 2 (可能不足以快速啟動)
   • Memory: 2Gi (載入模型後可能緊張)
   • 啟動時無 CPU boost

4. 【超時限制】
   • Cloud Run 有嚴格的健康檢查超時
   • 容器必須在限時內回應
   • 當前配置無法在時限內完成啟動
```

## 解決方案架構比較

```
┌─────────────────────────────────────────────────────────────────┐
│  方案 A: 增加啟動資源                                            │
└─────────────────────────────────────────────────────────────────┘

  部署參數調整:
  • --cpu-boost (啟動時使用更多 CPU)
  • --min-instances=1 (保持至少一個實例熱啟動)
  • --startup-cpu-boost (Cloud Run 新功能)

  優點: ✅ 修改最小
  缺點: ❌ 成本增加，冷啟動仍慢

┌─────────────────────────────────────────────────────────────────┐
│  方案 B: 將向量資料庫打包進映像                                  │
└─────────────────────────────────────────────────────────────────┘

  Dockerfile 修改:
  ```dockerfile
  # 建置階段
  FROM python:3.12-slim as builder
  COPY knowledge-base/ /app/knowledge-base/

  # 運行階段
  FROM python:3.12-slim
  COPY --from=builder /app/knowledge-base/ /app/knowledge-base/
  ```

  app_final.py 修改:
  ```python
  # 移除 GCS 下載邏輯
  # 直接載入本地向量資料庫
  if os.path.exists("knowledge-base/chroma.sqlite3"):
      rag_service_chroma.load_vector_store()
  ```

  優點: ✅ 啟動快速，邏輯簡單
  缺點: ❌ 映像更大 (+15MB)，更新困難

┌─────────────────────────────────────────────────────────────────┐
│  方案 C: 優化映像大小 (多階段構建)                               │
└─────────────────────────────────────────────────────────────────┘

  Dockerfile 優化:
  ```dockerfile
  # 階段 1: 建置階段
  FROM python:3.12-slim as builder
  RUN pip install --user torch torchvision --index-url ...

  # 階段 2: 運行階段 (只複製必要檔案)
  FROM python:3.12-slim
  COPY --from=builder /root/.local /root/.local
  ```

  優點: ✅ 映像較小
  缺點: ❌ 實現複雜，效果有限

┌─────────────────────────────────────────────────────────────────┐
│  方案 D: 混合方案 (推薦)                                         │
└─────────────────────────────────────────────────────────────────┘

  1. 將向量資料庫打包進映像 (方案 B)
  2. 增加啟動資源配置 (方案 A)
  3. 保持 min-instances=1 (至少一個熱實例)

  部署命令:
  ```bash
  gcloud run deploy nutrition-api \
    --image gcr.io/fooddata-92fa8/nutrition-api:latest \
    --cpu-boost \
    --min-instances=1 \
    --memory 2Gi \
    --cpu 2
  ```

  優點: ✅ 啟動最快，用戶體驗最佳
  缺點: ❌ 成本略高 (始終運行一個實例)
```

  │     ▼

        ▼

        │
        └─ Firestore: 用戶飲食日誌
